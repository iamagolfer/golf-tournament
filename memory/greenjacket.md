## 二、排名規則

```
淨桿 = 總桿(18洞) − 差點     低者勝
```

### 同淨桿時 → 可設定的優先順序系統

**這套設定只給綠夾克用。戒指盃的 tiebreak 邏輯完全不動。**

後台分成**兩組獨立清單**,各自可排序、可啟用/停用:

| 目前設定 | 順序 |
|---|---|
| **冠軍** | 1. 果嶺 PK |
| **其他名次** | 1. 後九總桿 → 2. 逐洞倒數 |

### 可選規則選單(9 條)

| id | 規則 | 備註 |
|---|---|---|
| `pk` | 果嶺 PK(人工決定) | **終止符** — 程式停下等後台指定勝出者 |
| `hcp_low` | 差點低的贏 | 與 `hcp_high` 互斥 |
| `hcp_high` | 差點高的贏 | 與 `hcp_low` 互斥 |
| `back9` | 後九總桿 | |
| `front9` | 前九總桿 | |
| `last6` | 後六洞總桿 | USGA 標準 |
| `last3` | 後三洞總桿 | USGA 標準 |
| `last1` | 最後一洞 | |
| `hole_countback` | 逐洞倒數(10A→18→17→…→1) | |
| — | 以上都相同 → 並列 | 固定保底,不可移除 |

標準 USGA countback = `back9 → last6 → last3 → last1`,一鍵可排出。

### 規則行為
- **`pk` 是終止符**:程式算不出 PK 結果,遇到就停 → 顯示並列 +「⛳ 待延長賽」→ 等後台指定勝出者
- **`hcp_low` / `hcp_high` 互斥**,UI 會擋
- **未打完 18 洞不套用 countback**,直接並列顯示
- **比賽進行中可隨時改設定**(會跳確認提示,排名即時重算)
- **目標:每一名都嚴格分出來**,不要並列

### ⚠️ 順序/洞數不寫死
`back9` / `front9` / `last6` / `last3` / `last1` / `hole_countback` 全部由資料庫的
球洞順序(section_order + hole_number)推導,**不寫死洞號**。

目前後九是 `10,11,12,13,14,16,17,18,10A`,所以逐洞倒數順序是:
```
10A → 18 → 17 → 16 → 14 → 13 → 12 → 11 → 10 → 9 → 8 → ... → 1
```
15 洞整修中,10A 是替代洞、也是實際打的最後一洞。
**下個月 15 洞開放後**,後台把球洞資料改回 `...14,15,16,17,18` 即可,
所有 countback 規則自動跟著變,程式一行都不用改。

### 殘留的極端情況
若兩人**每一洞桿數都完全相同**,任何 countback 都分不出來。
此時仍會並列 — 建議在「其他名次」清單最後補一條 `hcp_low` 當保底。(待 Albert 決定)

## 八、技術決定

1. **比賽分流** — `tournament.slug`(`ring` / `greenjacket`)。API 用 `?t=<slug>` 指定,
   沒帶預設 `ring`,所以戒指盃前端零修改。
2. **排名邏輯分家** — 新檔 `logic/gjRankings.js`,`logic/rankings.js` 完全不動。
3. **前端複製獨立** — `pages/gj/`,不與戒指盃共用元件(6 天內求安全)。
4. **`holes.hole_label`** — 新欄位。原本 `hole_number INTEGER` 存不下 "10A"。
   `hole_number` 保留 1–9 管排序,`hole_label` 存顯示文字。戒指盃沒填就照舊。
5. **綠夾克後台隱藏「今日賽程」開關** — 那是戒指盃切 3 個 9 洞用的,
   18 洞賽事誤關會讓一半成績從排名消失。
6. 綠夾克狀態流程簡化:`setup → playing → finished`。
7. **新欄位總表**
   - `tournament`: `slug`, `name`, `playoff_winner_id`, `show_wildcard`,
     `tiebreak_champion`(JSON), `tiebreak_others`(JSON)
   - `holes`: `hole_label`
   - `players`: `wildcard`, `tee`
   - 新表: `champions`, `champion_results`
